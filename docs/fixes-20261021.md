## 2. 设计决定

### 2.1 `slugify` 保留 Unicode 字母

```js
String(value).normalize('NFKD')
  .toLowerCase()
  .replace(/[^\p{L}\p{N}._-]+/gu, '-') // 保留中文等 Unicode 字母
  ...
```

行为：

| 输入 | 输出 |
|---|---|
| `Loss Curve v2!` | `loss-curve-v2`（不变） |
| `航磁补偿` | `航磁补偿`（原为 `topic`） |
| `PINN 求解器` | `pinn-求解器`（原为 `pinn`） |
| `Müller` | `mu-ller`（与旧版一致；不剥离音标，避免与 `Muller` 撞名） |
| `a/b` | `a-b` |
| `../etc/passwd` | `etc-passwd`（路径分隔符仍被替换） |
| 超长（>120 字节） | 截断到 ≤112 字节 + `-<6 位哈希>`（防 `ENAMETOOLONG`） |
| `  ` | `item`（fallback 不变） |

ASCII 输入的输出保持不变，既有目录与测试不受影响。

### 2.2 `/paper` 出口契约改为 key-agnostic

`paper-note:核心主张|方法要点|局限` 的校验步骤：

1. `literature/notes/*.md` 里存在**本次 loop 新建或更新**的笔记（相对 loop 创建时的 `baseline.notes` 快照；旧 loop 无快照时退回 `openedAt` 精确比较）
2. 模板三节 **核心主张 / 方法要点 / 局限** 每节有 ≥10 个非空白字符（空模板不算）
3. 笔记文件名（即 citekey）在 `literature/references.bib` 有对应条目

理由：citekey 由元数据决定（第一作者姓 + 年份 + 关键词），命令入口在解析 DOI/标题之前无法知道；
用参数 slug 当 key 只能产出 DOI 串或 `paper`，且与 `lit_bib` 的自动规则冲突。
模板三节来自 `lit-lib` / `literature-retrieval` 技能，不是旧文档里的「方法/结果/局限」。

### 2.3 校验 DSL 扩展

| 校验项 | 语义 |
|---|---|
| `contains:<path>:<a>|<b>` | 文件含**全部**子串（忽略大小写；ASCII 标签按词边界，`gap` 不匹配 `Singapore`） |
| `contains-any:<path>:<a>|<b>` | 文件含**任一**子串（忽略大小写） |
| `markdown-table:<path>` | 至少一张 Markdown 表格（表头行 + 分隔行） |
| `file-since-open:<path>` | 文件存在且 mtime ≥ loop 开启时间 − 2s（防复用上一轮旧产物；2s 容差兼容粗粒度 mtime） |
| `min-citations:<path>:<n>` | 文件里不同 citekey 数量 ≥ n（与 `citations-bib` 同一解析器） |
| `citations-bib:<path>` | **只扫该文件**：引用的 citekey 都能在 bib 找到 |
| `bib-entry:<key>` | key 做正则转义；同时接受 `{}` 与 `()` 条目 |
| `paper-note:<a>|<b>` | 见 2.2 |
| `cite-check` / `cite-check-deep` | 全项目引用校验（只用于 `/write`，不用于 `/survey`） |

`/survey` 不再用全项目 `cite-check`：它会扫描所有 `.md/.tex`，别的笔记里的悬空引用会把调研 loop 卡死。
`/survey` 改用 `citations-bib`，作用域限定在报告文件本身。

### 2.4 命令契约变化

| 命令 | 变化 |
|---|---|
| `/survey` | 增加 `markdown-table` 与 `citations-bib`；步骤补“用 lit_bib 落 bib” |
| `/paper` | `paper-note` 取代固定 `file:` + `bib-entry:`；步骤按 literature-retrieval 模板精读 |
| `/derive` | `contains-any` 增加 小参数展开 / 不确定度 / 蒙特卡洛 |
| `/write` | 目标文件改用 `file-since-open`，防止沿用旧报告直接关闭 |

## 3. 独立审查后的第二轮修复（2026-10-21）

| 审查项 | 修复 |
|---|---|

| `/survey` + `cite-check` 全项目扫描，别的笔记悬空引用会卡死 | 改为 `citations-bib`，只扫报告 |

| loop/命令/强制层测试不在 CI | `npm run check` 纳入 4 个测试文件 |
| 括号 BibTeX（`@article(key,`）不支持 | `bib-entry` / `paper-note` 同时接受 `{}` 与 `()` |

| `/derive`（以及 `/survey` `/write`）可复用上一轮旧产物直接关闭 | 新增 `file-since-open`，要求本次新建/更新 |
| `contains:gap` 会误匹配 `Singapore` | ASCII 标签按词边界匹配 |

## 4. 兼容性

- ASCII slug 不变；`Müller` 仍为 `mu-ller`（与旧版一致）
- 既有 loop JSON 不迁移（新校验只出现在新 loop）
- `paper-note` 用 loop 创建时的笔记快照（`baseline.notes`）：**未被改动的旧笔记**不会被算作本次工作；
  旧 loop（无 `baseline`）退回 `openedAt` 精确比较。`touch` 仍可绕过（非对抗场景可接受）。
- `paper-note` 不绑定 `loop.arg`：编辑笔记 B 也能关闭 `/paper A`；需要严格绑定时可后续加 `--key`。
- `markdown-table` 是结构校验（存在表格），不判断表格内容是否真是「方法对比」。
- `contains` 的 ASCII 标签按词边界；中文标签仍是子串匹配。
- 符号链接未做 `realpath` 约束（`withinRoot` 是词法检查），工作区内的链接由用户自己负责。
- 0.3.0 之前用非 ASCII 工件名的数据会落在 `research/records/item`（旧 `slugify` 的 fallback）；
  新名字会新建目录。需要时手工迁移，或先用旧名 `record_verify` 再改名。
