## 2. 设计决定

### 2.1 `slugify` 保留 Unicode 字母

```js
String(value).normalize('NFKD')
  .replace(/\p{M}+/gu, '')              // 去掉分解出来的组合音标
  .toLowerCase()
  .replace(/[^\p{L}\p{N}._-]+/gu, '-') // 保留中文等 Unicode 字母
  ...
```

行为：

| 输入 | 输出 |
|---|---|
| `Loss Curve v2!` | `loss-curve-v2`（不变） |
| `航磁补偿` | `航磁补偿`（原为 `topic`） |
| `PINN 求解器` | `pinn-求解器`（原为 `pinn`） |
| `Müller` | `muller`（改进：原为 `mu-ller`） |
| `a/b` | `a-b` |
| `../etc/passwd` | `etc-passwd`（路径分隔符仍被替换） |
| `  ` | `item`（fallback 不变） |

ASCII 输入的输出保持不变，既有目录与测试不受影响。

### 2.2 `/paper` 出口契约改为 key-agnostic

`paper-note:方法|结果|局限` 的校验步骤：

1. `literature/notes/*.md` 里存在**本次 loop 新建或更新**的笔记（mtime ≥ `openedAt` − 2s）
2. 该笔记含全部三节（忽略大小写）
3. 笔记文件名（即 citekey）在 `literature/references.bib` 有对应条目

理由：citekey 由元数据决定（第一作者姓 + 年份 + 关键词），命令入口在解析 DOI/标题之前无法知道；
用参数 slug 当 key 只能产出 DOI 串或 `paper`，且与 `lit_bib` 的自动规则冲突。

### 2.3 校验 DSL 扩展

| 校验项 | 语义 |
|---|---|
| `contains:<path>:<a>|<b>` | 文件含**全部**子串（**忽略大小写**） |
| `contains-any:<path>:<a>|<b>` | 文件含**任一**子串（忽略大小写） |
| `markdown-table:<path>` | 至少一张 Markdown 表格（表头行 + 分隔行） |
| `paper-note:<a>|<b>` | 见 2.2 |
| `bib-entry:<key>` | key 做正则转义（DOI 里的 `.` 不再当通配符） |

### 2.4 命令契约变化

| 命令 | 变化 |
|---|---|
| `/survey` | 增加 `markdown-table` 与 `cite-check`；步骤补“用 lit_bib 落 bib” |
| `/paper` | `paper-note` 取代固定 `file:` + `bib-entry:`；步骤补“先 lit_doi 定 citekey” |
| `/derive` | 增加 `contains-any`（至少一条验证路线） |

## 3. 兼容性

- ASCII slug 不变；既有 loop JSON 不迁移（新校验只出现在新 loop）
- `paper-note` 用 mtime 判断“本次新建/更新”，2 秒容差；旧笔记不会被误判为新
- `contains` 变宽松，不会让既有契约更难通过
