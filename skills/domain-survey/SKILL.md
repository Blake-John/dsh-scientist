# 领域调研（Domain Survey / Landscape）

目标：把「一个方向」变成**可决策的地图**——哪里是共识、哪里在打架、哪里是空白、从哪切入最省力。
产出不是论文摘要堆砌，而是有判断的结构化文档。

## 何时用

- 进入新方向 / 换子领域 / 判断某个 idea 是否已被做过
- 写综述的骨架、基金申请的背景、组会简报
- 评估一个「gap」是真空白还是自己没检索到

## 工作流

### 0. 定框（先写下来，再检索）
用 3–6 行写清：研究对象、要回答的决策问题、时间窗（默认近 5 年 + 奠基工作）、
学科边界（哪些相邻领域要纳入/排除）。存到 `reports/landscape-<topic>/scope.md`。
**决策问题**决定后续检索式；没有决策问题的调研必然发散。

### 1. 检索（多源并发，而非一个源翻十页）
用 `lit_search` 一次打多个源（`sources` 参数），按用途分工：

| 用途 | 源 | 检索式要点 |
|---|---|---|
| 建骨架（综述/高被引） | Crossref（`sort: "cited"`） | `survey`/`review` + 领域词；按被引排序 |
| 定前沿 | arXiv（`sort: "date"`） | 近 12–18 个月 |
| 补全（跨库漏检） | Crossref | DOI/标题回查，补元数据 |
| 生医 | PubMed、Europe PMC | 领域词 + MeSH 术语 |

- 检索式写进 `literature/queries.md`，同义词、缩写、旧称都要覆盖（例：`diffusion model` /
  `score-based generative model` / `denoising diffusion`）。
- 至少两轮：第一轮宽（找流派），第二轮针对每个流派窄检索（找代表作与最新进展）。
- 记录每次检索的源、式、命中数；**没命中也是结论**（可能是术语不同，也可能真没人做）。

### 2. 聚类成流派
把命中按「方法家族」而不是按年份分组。每个流派回答四件事：
核心假设是什么 / 解决了什么 / 代价是什么（算力、数据、可解释性）/ 谁在推进。
流派之间存在**互斥假设**时，单独列出来——那通常是真正的研究机会。

### 3. 时间线
只画「转折点」：第一篇提出该思路的工作、性能跳变的节点、范式被推翻/合并的节点。
每个节点一句话 + 引用。时间线用来判断「现在是早期还是晚期」——晚期方向慎入。

### 4. 方法/指标对比表
选 4–8 篇代表作，做一张表：方法 / 关键假设 / 数据集或实验体系 / 指标 / 报告的最优值 /
局限（作者自己承认的 + 你判断的）。**不要只抄 abstract 里的数字**，注意不同论文的实验设置
不可直接比较——不可比就在表里标注。

### 5. 开放问题与 gap 判定
对每个候选 gap 做三问：
1. 有没有人做过（检索原始说法 + 同义说法）？
2. 如果没人做，是没价值还是没条件（数据/算力/理论障碍）？
3. 最小可行切入点是什么（能在一到两周内验证的最小实验/最小推导）？
把 gap 分成「真空白 / 已有人做但做得不好 / 伪空白（术语差异）」三类。

### 6. 产出

命令闭环的出口是**单文件主报告** `reports/landscape-<topic>.md`；
`reports/landscape-<topic>/` 下的 scope.md / timeline.md / refs.md 是可选的中间工作笔记。

```
reports/landscape-<topic>.md     主报告（命令闭环的出口，下节模板）
reports/landscape-<topic>/       可选工作笔记
  scope.md            决策问题与边界
  refs.md             引用清单（citekey → DOI/arXiv id → 一句话贡献）
  timeline.md         转折点时间线
```

`reports/landscape-<topic>.md` 结构：
1. 一句话结论（这个方向现在处于什么状态、值不值得做、从哪切入）
2. 边界与决策问题
3. 流派地图（每派：假设/贡献/代价/代表工作）
4. 时间线（转折点）
5. 对比表（Markdown 表格）
6. 开放问题与 gap 判定（三类）
7. 推荐的下一步（最小验证动作，具体到「跑什么/读什么/推什么」）
8. 不确定性声明（检索覆盖度、没读到的语言/库、可能漏的术语）

**引用格式**：正文统一用 key 式 `[@key]` 或 `\cite{key}`，条目用 `lit_bib` 落到
`literature/references.bib`；`/survey` 的出口校验会检查报告里的每个 citekey 都能在 bib 找到。
不要用编号制 `[1]`——`min-citations` 只统计 key 式引用。

最后 `record_save` 归档报告（notes 写明检索日期与源），结论引用工件名与版本。

## 质量红线

- 每个论断都能落到一条引用；没有引用的判断标「作者判断（无文献支撑）」。
- 区分「领域共识」「个别论文主张」「我的推断」——三种语气不能混。
- 不写"近年来取得了显著进展"这类无信息量的话。
- 报告里的数字必须注明来源与实验设置；跨论文数字不可比就明说。
- 检索覆盖度写清楚：用了哪些源、哪些没访问到（付费墙/语言/限流）。

## 常见失败

- **只用一个源**：arXiv 上没有的工程工作、S2 索引不到的旧文献都会漏。
- **只读综述**：综述有 1–2 年滞后，前沿必须自己扫最近的。
- **把「我没搜到」当成「没人做」**：换术语、换源、查引用网络再下结论。
- **调研变成读书笔记**：没有决策结论的调研等于没做。
