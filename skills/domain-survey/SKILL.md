# 领域调研（分阶段 Domain Survey）

目标：把「一个方向」变成**可决策的地图**——哪里是共识、哪里在打架、哪里是空白、从哪切入最省力。
产出不是论文摘要堆砌，而是有证据链、分阶段推进的结构化文档。

## 分阶段命令

**一次只做一个阶段，不要提前做后续阶段。**

| 阶段 | 命令 | 产物 | 关键动作 |
|---|---|---|---|
| 1 | `/survey-scan` | `scope.md`、`sources.md` | 定框 + 网络调研（web_search / read_page），≥8 个 URL 来源 |
| 2 | `/survey-scholar` | `queries.md`、`candidates.md` | Crossref/arXiv/PubMed/Europe PMC 检索，≥12 篇候选 |
| 3 | `/survey-map` | `landscape.md` | 流派、时间线、对比表、gap 三类 |
| 4 | `/survey-papers` | `papers.md` | 论文总述、纳入/排除、深读队列（≥10 篇） |
| 5 | `/survey-report` | `report.md` | 综合已有产物成文，不重新检索 |
| 深读 | `/paper <citekey>` | `knowledge/literature/notes/<citekey>.md` | 单篇精读 |

`/survey <主题>` 是状态页；`/survey --next` 执行下一阶段。阶段严格顺序；`--force` 会把未完成前序标 `skipped`，状态页会提示证据链不完整。

## 总原则

- 所有产物在 `knowledge/surveys/<topic>/`（v2 布局）；不要散落到其他目录。
- 每个阶段结束前调用 `loop_close()`；系统会标记阶段完成并提示下一条命令。
- 一个阶段只回答自己的问题，不要把下一阶段的结论提前写掉。
- 证据分三类：学术论文（bib citekey）、网页资料（sources.md 的 URL）、作者判断（明确标注）。
  网页资料**不要**伪装成 `references.bib` 条目。

## 1. `/survey-scan`：定框 + 网络调研

### 1.1 定框（先写 `scope.md`）
用 3–6 行写清：

- 研究对象与**决策问题**（这次调研要支持什么决定）；
- 学科边界（哪些相邻领域纳入/排除）；
- 时间窗（默认近 5 年 + 奠基工作）；
- 纳入/排除标准；
- 3–5 组检索式（领域词、同义词、缩写、旧称、英文/中文）。

没有决策问题的调研必然发散；先把问题钉死。

### 1.2 网络调研（`web_search` / `read_page`）
先用 `web_search` 做宽检索，至少覆盖：

- 领域综述 / 教程 / 课程；
- 代表实验室、公司、开源项目；
- benchmark、竞赛、排行榜；
- 新闻/博客里的工程实践与失败经验。

对关键页面用 `read_page` 读正文，不要只看搜索摘要。把每一个来源写进 `sources.md` 表：

| # | 标题 | URL | 类型 | 日期 | 可信度 | 用途/关键结论 |
|---|---|---|---|---|---|---|

类型用：`lab` / `blog` / `news` / `benchmark` / `官方文档` / `教程`。
可信度：`高（一手/官方）` / `中（二手但有署名）` / `低（匿名/营销）`。
**≥8 个不同 URL**；标出网络资料的覆盖盲区，留给 `scholar` 阶段。

不要在这一步写流派地图、论文总述或最终报告；不要读论文全文。

## 2. `/survey-scholar`：学术检索 + 候选论文

### 2.1 检索式（`queries.md`）
把检索式写成表：

| 源 | 检索式 | 命中数 | 日期 | 备注 |
|---|---|---|---|---|

至少两轮：

- 第一轮宽：`survey` / `review` + 领域词，Crossref 按被引排序，找综述与高被引；
- 第二轮窄：按流派/方法名检索 arXiv 近期，找代表作与最新进展。

同义词、缩写、旧称都要覆盖；没命中也是结论（可能是术语不同，也可能真没人做）。

### 2.2 候选论文（`candidates.md`）
用 `lit_search` 多源并发；用 `lit_doi` 核对元数据；用 `lit_bib` 把候选论文落到
`knowledge/literature/references.bib`。写候选表：

| citekey | 年份 | venue | 类型 | 被引 | 为什么入选 |
|---|---|---|---|---|---|

类型：`survey` / `method` / `baseline` / `dataset` / `theory` / `application`。
**≥12 个不同 citekey**；每个 citekey 必须能在 bib 找到。

不要在这一步做流派聚类或写报告；只产出检索式与候选表。

## 3. `/survey-map`：流派、时间线、对比、gap

读 `candidates.md` 与 `sources.md`，产出 `landscape.md`：

1. **流派地图**：按方法家族分组，每派写核心假设 / 解决什么 / 代价（算力、数据、可解释性）/ 谁在推进。
2. **时间线**：只画转折点——第一篇提出该思路、性能跳变、范式被推翻/合并；每个节点一句话 + 引用。
3. **方法/指标对比表**：选 4–8 篇代表作，列方法 / 关键假设 / 数据集 / 指标 / 报告最优值 / 局限。
   不同论文实验设置不可比就标注，不要硬比数字。
4. **gap 候选**：每个 gap 做三问——有人做过吗？没价值还是没条件？最小可行切入点是什么？
   分成「真空白 / 已有人做但做得不好 / 伪空白（术语差异）」。

**≥5 个 citekey**；不要逐篇精读，不要写最终报告。

## 4. `/survey-papers`：论文总述 + 深读队列

读 `landscape.md` 与 `candidates.md`，产出 `papers.md`：

| citekey | 年份 | venue | 角色 | 一句话贡献 | 纳入/排除 | 深读优先级 | 理由 |
|---|---|---|---|---|---|---|---|

- **≥10 篇**；纳入/排除都要写理由；
- 建「深读队列」：选 5–10 篇，标 `P0/P1/P2`，说明为什么值得读；
- 所有 citekey 在 bib；不要读全文，不要写 `report.md`。

深读交给 `/paper <citekey>`，每篇一个笔记；不要在 `papers` 阶段批量读全文。

## 5. `/survey-report`：综合报告

读前四个阶段的产物，写 `report.md`：

1. 一句话结论（这个方向现在什么状态、值不值得做、从哪切入）
2. 边界与决策问题
3. 流派地图
4. 时间线
5. 方法对比表
6. 开放问题与 gap 三类判定
7. 推荐的最小下一步（具体到读什么/跑什么/推什么）
8. 不确定性声明（检索覆盖度、没访问到的源、可能漏的术语）

**≥5 个 citekey**；不重新检索；缺证据标「作者判断/待补」。
网页资料标注「见 sources.md」，不要伪造 bib 条目。

## 质量红线

- 正文引用统一写 `[@key]`（或 `\cite{key}`）；`map`/`report` 的 `min-citations` 只统计这种格式，
  表格里的代表工作也至少用 `[@key]` 标一次。
- 每个论断能落到一条引用；没有引用的判断标「作者判断（无文献支撑）」。
- 区分「领域共识」「个别论文主张」「我的推断」——三种语气不能混。
- 不写"近年来取得了显著进展"这类无信息量的话。
- 报告里的数字注明来源与实验设置；跨论文数字不可比就明说。
- 检索覆盖度写清楚：用了哪些源、哪些没访问到（付费墙/语言/限流）。

## 常见失败

- **只用一个源**：arXiv 上没有的工程工作、旧文献都会漏。
- **只读综述**：综述有 1–2 年滞后，前沿必须自己扫最近的。
- **把「我没搜到」当成「没人做」**：换术语、换源、查引用网络再下结论。
- **跳阶段**：scan 没做完就写 report，最后引用和 gap 都站不住。
- **把网页当论文引用**：网页进 `sources.md`，学术论断用 bib。
